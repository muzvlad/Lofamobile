# Spec 002: Публикация проекта на main

## Цель

Сделать `main` — ветку по умолчанию на GitHub — витриной проекта: перенести туда содержимое рабочей ветки `master` без потери истории и без перезаписи чужих коммитов.

## Проблема

- Default branch репозитория — `main`, но в ней только автоматически созданный README из трёх строк.
- Весь проект и подготовленные правки находятся в `origin/master`, а истории `main` и `master` не связаны.

## Изменения

1. Создать ветку `public-main` от `origin/main`.
2. Слить `origin/master` в `public-main` через merge с `--allow-unrelated-histories`, сохранив обе истории.
3. При конфликте README оставить описание проекта из `master`, а не stub GitHub.
4. Перенести spec в архив, обновить записи в `memory.md` и `memory/25.11.2026/notes.md`.
5. Закоммитить и запушить результат в `origin/main`.

## Критерии готовности

- `origin/main` содержит проект, README, удалённый `GIT_INSTRUCTIONS.md` и защиту JWT.
- История `main` сохраняет исходный коммит GitHub.
- Коммит `origin/master` не перезаписан.

## Риски

- Merge несвязанных историй создаёт merge-коммит; это ожидаемо и безопасно.
- В рабочей директории присутствуют локальные артефакты (`server.exe`, `admin.exe`, `codequest.db`). После merge их перехватит `.gitignore` из `master`; удалять их не нужно.
- Тесты не запускались: в окружении нет установленного Go.
