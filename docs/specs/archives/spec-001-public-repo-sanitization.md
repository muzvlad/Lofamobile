# Spec 001: Подготовка репозитория к публикации

## Цель

Сделать репозиторий LofaMobile безопасным для публикации на GitHub и добавить короткое человеческое описание проекта.

## Проблема

- `GIT_INSTRUCTIONS.md` раскрывает локальный путь пользователя Windows, GitHub-логин и содержит инструкцию по хранению токена в URL remote. Реального токена в истории коммитов нет.
- `.env.example` содержит правдоподобный дефолтный JWT-секрет.
- В `internal/config/config.go` используется захардкоженный dev-секрет: без `JWT_SECRET` токены подписывались известным значением.
- В корне отсутствует README, а шаблоны `.gitignore` не покрывают локальные остатки сборки.

## Изменения

1. Удалить `GIT_INSTRUCTIONS.md`.
2. В `.env.example` заменить значение `JWT_SECRET` на явный плейсхолдер.
3. В `internal/config/config.go` заменить константный dev-секрет на случайный, сгенерированный через `crypto/rand`; в production переменная по-прежнему обязательна.
4. Создать короткий `README.md` без канцелярита.
5. Дополнить `.gitignore` игнорированием `*.exe~` и `auth_cov`.
6. Зафиксировать решение в `memory/25.11.2026/` и `memory.md`.
7. Закоммитить изменения и выполнить push в `origin/master`.

## Особенность выполнения

Локальная ветка `master` содержала более старую версию разработки, а `origin/master` — новую (v2.1.0). Чтобы не перезаписывать более свежую работу, правки применены на отдельной ветке `public-prep`, созданной от `origin/master`. Локальные коммиты сохранены в ветке `local-dev-backup` и не отправлялись.

## Критерии готовности

- `go test ./...` проходит (проверка невозможна: в окружении нет установленного Go).
- Реальные секреты, токены, имена пользователей и локальные пути в отслеживаемых файлах отсутствуют.
- `README.md` описывает проект, запуск и тесты.
- Изменения отправлены в удалённый репозиторий.

## Риски

- Случайный секрет без `JWT_SECRET` означает, что токены станут недействительными после перезапуска сервера. Для локальной разработки это приемлемо, для production секрет задаётся через env и проверяется при старте.
- Push может потребовать авторизацию GitHub; если учётные данные не настроены, результат будет сообщён пользователю без изменения remote.
